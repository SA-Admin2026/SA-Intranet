Alt Labels: Draft guidelines/suggestions for adding/modifying content on the SA Wiki,

We generate, harvest and receive a great deal of content. This page is about where we should put it, by type to maximize the odds that someone can find it when needed and minimize the risk of disclosing it.

(there was some discussion about it being easier to search for things on the wiki, which might be true, but it might be because there are 1,000 documents on the wiki and 400,000 on the shared drive. )

# Client Material

All client material, that is any data they give us or anything we generate in the course of an engagement should go on the shared drive, in a folder under ClientsAndPartners. The shared drive is encrypted, backed up and has gone through some audits by clients who do this kind of thing.

You should consider your laptop to be a cached local copy. Periodically, and at the end of a project you should synch up with the shared drive and delete any material no longer needed on your laptop. This data is a liability and we should minimize our risk if these laptops were to go missing. By the way, they should be encrypted as well.

A good idea for organizing is to have the first level under the client be for projects, and a good practice for project naming would be to have the date in the name (as 2021\_Jan\_MSMap or so). A convention that has worked well is to have a folder for the signed contracts (this could be one at the client level or one per project). In the project folder a nice next level is:

- MaterialTheyveGivenUs
- MateriaWeFound
- MaterialWeCreated

The middle one for things we found on the web about the client, project, domain etc

# Marketing Material

All marketing material, including proposals and conference presentations should be stored on the shared drive. This is a resources we want to be able to mine and reuse. The key subfolder is \_Proposals where all drafts, especially final drafts send to prospects should be.

# Offerings

This directory contains all the products and services we offer. I’m about to rearrange it so that the old stuff is not so prominent.

# Legal and Accounting

All legal and accounting information should be stored on the shared drive. This includes quickbooks itself, backups, correspondence with tax authorities etc etc.

Client contracts should be on the shared folder under each client.

# HR

All HR materials on applicants, recruits and employees should be on the shared drive. Some of this will be in a special area restricted to HR, and hopefully someday the President.

Benefit information is also kept here

# Payroll

Detailed information about specific pay rates and payrolls are kept in the Presidents special place on the shared drive.

# Internal Systems

Information about our internal systems, including ontology and design for the systems we use to run our business, and the many spreadsheets we use to conduct day to day business are to be kept on the shared drive under InternalSystems

# Code, including Ontologies

Code and ontologies should be in a github repo. We should clear with clients before putting any of their code or ontologies on any publicly reachable github repo

# “How to”'s

Advice for how to install and use software, how to connect to networks and the like should be on our Atlassian wiki.

Also non-sensitive client info like, how to get to a client, best way to get from laguardia to mid town etc, should also be on the wiki.
