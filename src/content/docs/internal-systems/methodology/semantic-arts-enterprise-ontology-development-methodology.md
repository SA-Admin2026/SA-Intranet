# Objective

Pull together our experience over the last decade, so that we can all work to a common outline and refine it.

# Approach to methodology

- This is not meant to be a detailed proscriptive step by step cookbook
- It will primarily be organized around interim deliverables
- We will start with a general discussion of why we are building the interim deliverable, and what some key things to look for in the deliverable would be
- Then we will have as many examples as we can find, with some critiques
- Finally for many of them we will have the starting point QA checklist for the deliverable
- Most deliverables have to be elicited, drafted, reviewed, revised and reviewed again. There will be multiple deliverables in different stages at the same time, so this scheduling will be tricky. We want to get to where we have a predictable, but still fast enough, tempo for completing this work.

# General Approach to Enterprise Ontology Building

We have found the following general approach to work well:

- Think big/ start small – Build the Enterprise ontology in parallel with the first expression of it. This gets something tangible that people can relate to early on, without boxing us into the POC cul-de-sac
- Start with gist
- Concentrate on “covering concepts” that is, try not to introduce orphans that just seem to come up
- Start from a gestalt of the enterprise and key domain, and allow that to drive the design, not the existing application data models
- But ultimately the model must contain all the useful business information in the application systems

While in initial build mode, speed more important than control, when shift to production, control more important than speed

# Historical notes

- Historically we have relied on very experienced people who could short cut many of the steps in this methodology
- What we are attempting to do here is make the tacit, explicit
- Some of this might be overkill, but lets try this and get some feedback on the time required and value to each step.
