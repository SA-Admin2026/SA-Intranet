# Introduction

The gistCyber ontology is meant to address the domain of discourse specific to Cyberspace concepts. Typically, the Cyber Domain is taken to mean the more specific domain of security in cyberspace, or simply cybersecurity. There are many sub-domains that can be implemented by extension of gistCyber. For example, to mention a few:

- Software & Hardware Vulnerability
- Attack Patterns
- Risk and Risk Analysis
- Controls and Mitagations
- Enterprise Intelligence and Business Processes
- Threat Intelligence
- Insider Threat
- Application Security
- eCommerce
- Trust and Zero-Trust
- Incident Response
- Security Operations
- National Security
- Enterprise Security
- Threat Scenario Development
- Red and Blue Team Operations
- many more

It is anticipated the the gistCyber ontology will be the mid-level ontology that these more specific domains can use to create equivalent and subclasses.

## Influence of the DoD-IC Ontology Foundry

Government agencies are required (eh…strongly advised) to use ontologies from the DoD-IC Ontology Foundry. Hence, we want to create gistCyber so that it can be summitted and accepted into the foundry. This will open the door for these agencies to use gistCyber in the data management systems. To get gistCyber into the DOD-IC Ontology Foundry in must be compliant with Basic Formal Ontology (BFO) and Common Core Ontologies (CCO). This have influenced how we are approaching the development of gistCyber.
