Many of these tasks are going to require administrative visibility from the developers, so contact them if you can’t see certain options listed below. This is also changing rapidly right now during development so instructions may not be exact.

Another important Spark reminder is that you never want to mess with something that affects a “closed” pay period. This means most changes to rates, positions, projects, etc should only affect dates moving forward and not into the past.

## New Employee

Navigate to the HR tab, click the “Employee” view (looks like an ID card). Enter their name, title, start date, etc. Make sure to enter their work email, location, position, and rate assignments. The default share multiplier is .5 unless otherwise instructed. Get their Rippling ID from Rippling directly.

These instructions are the same for sub-contractors, you will just need to start from the “Contractor” view.

## Employee Modifications

When an employee’s position or pay changes, it should be updated in Spark. Use the “Employees” view (magnifying glass icon) to locate the employee, and the pencil to make a change.

Make sure to make the end date on the previous position or rate the same as the start date of the new one. These changes should only be made generally on the first Friday of a new pay period (or you can go back and change the date to be the beginning of the current period). This is important as many of the queries rely on this fact right now.

## Terminate Employee

Go to the “Employees” view (magnifying glass icon) and locate the employee. Set the end date on their employee form, as well as each position and rate. Generally, these should not be mid-pay period.

## New Project

Go to the “Projects” tab, then to the “Project” view. You’ll need to create a title for the project (should include the client name). Choose a client contact and client (or create if they are not already in the dropdown). Set a planned start and end. Generally, set the project to billable unless it is internal.

Make sure to add project assignments. Dave should be on most projects. Do not set an end date on each individual person.

Write Off default is 0.00. Enter a task (description is required).

You’ll need to assign a commission assignment to be able to save. Select something as a placeholder if you aren’t sure initially. New projects are worth more than renewals, and size matters. If unsure which option to select run it by Dave/Mark.

When assigning sales contributions, there are 5 categories. Each weighs 20% in the commission assignment and may be assigned to anyone on the team

Acquired: Who brought the client/sponsor to Semantic Arts

Estimate & Proposal: Who was primarily responsible for developing the proposal and price estimate for this project

Nurtured: Who is primarily responsible for connecting and nurturing the client with a goal for future work

Shaped: Who worked to shape the current project and determine scope and effort

Shepherded: Who shepherded the project through the sales process all the way to started.

**NOTE:** These must be assigned before payroll to ensure the commissions are calculated properly.

**REMINDER: Don’t forget to go to the Project Specific Billing Rates view to make sure the rates are correct and don’t need modified**

## Project Changes

The main thing to watch out for is the end date on a project. If a project runs longer than expected, billing to the project will be unavailable on the assigned end date. You’ll need to extend the date to allow others to charge to it.

You can also set an end date on a particular employee’s assignment if they leave a project or leave the company. This prevents them from charging to a project. Make sure to add a new person that comes on with a start date and leave end date blank.

**Write Offs**

Probably one of the things to pay closest attention to. Two scenarios:

1. When you are aware of a write off (positive or negative) at the start of a project, make sure to add the correct amount (as a decimal) on the project. You also need to navigate to the “Project Billing Rates” view and adjust each individual’s rate to match the correct write off amount
2. When a write off is discovered mid-project (due to an overrun, mistake, etc). Two things are necessary. Navigate to the “Project Billing Rates” view. Set an end date on the old rate and create a new rate with the same start date and no end date. If the ER for the project needs adjusted backwards, go to the “Earned Revenue Adjustments” view. You’ll need to create the correct adjustment amount for each employee. Generally this will be the same across the board but not always.

**No Cost Extensions**

When a project runs longer than expected, end the current Project Assignments as of today. Then, enter new PAs from today to expected end with no entry for consumption (days).

If consumption changes during a project, end original PAs and start new ones with new consumption from today to end date of project.

## End Project

Not much to it, you generally only need to change the end date to be today so employees can no longer charge to the project. Make sure to download the “Project ER by Pay Period” to follow the closing procedure in QuickBooks.
